# OllamaをAgentic RAGのバックエンドにする

> 出典: [Ollamaをagentic RAGのバックエンドにする：完全ローカル完結エージェント | Zenn](https://zenn.dev/libercraft/articles/20260803-ollama-local-agentic-rag-backend)

## 主題

金融・防衛・医療などの機密性が高い業界において、外部クラウドへデータを送信せずに、
Ollama によるローカルLLMのみで [[Agentic RAGとは|Agentic RAG]] の検索エージェントを構築する方法論。

## 扱われている主要技術

| 技術 | 役割 |
|------|------|
| Ollama | ローカルLLM実行エンジン |
| Agentic RAG | 検索に基づくエージェント推論 |
| ツール呼び出し（Tool Calling） | 構造化関数実行 |
| ベクトル埋め込み | 意味的検索（`nomic-embed-text`） |
| 量子化 | ハードウェア最適化 |

## 記事の構成

1. **制約条件の整理**: ローカルモデル選定時の注意点（Qwen3 14B以上を推奨、小型モデルは精度低下リスクあり）
2. **実装手法**: Python の型ヒント＋docstring から自動的に JSON Schema を生成し、ツール呼び出しを実現
3. **エージェントループ**: モデルの応答 → ツール実行 → 結果フィードバックの循環構造
4. **検索の多層化**: キーワード検索（grep）とベクトル検索を使い分け
5. **運用課題への対処**:
   - エアギャップ環境でのモデル持ち込み
   - コンテキスト長制約への対応
   - ストリーミング表示
   - マルチユーザー時のGPUリソース管理（Semaphoreで同時実行数を制限）
   - 監査ログの必要性
6. **品質保証**: 回帰テストでモデル更新時の性能確認

## コードサンプルの概要

**ツール定義の例**（型ヒントとdocstringだけでOllamaが自動的にスキーマを生成）:
```python
def search_local_documents(query: str) -> str:
    """社内文書をキーワード検索"""
    # grep を用いたローカル検索実装
```

**エージェントループの骨組み**:
- メッセージ履歴にユーザー質問を追加
- モデルに `tools` パラメータで利用可能なツールを指定
- `tool_calls` が生成されたら実行し、結果をメッセージに追加
- `tool_calls` が空になるまでループ

**品質検証の工夫**: ツール未使用での回答は幻覚（ハルシネーション）の疑いとして警告する。

## 重要なポイント

| ポイント | 要点 |
|---------|------|
| モデルサイズの選択 | 8B は開発用、14B 以上が本番推奨 |
| 幻覚検出 | ツール呼び出しログが空 ≠ 文書参照あり、要検証 |
| 複数検索方式 | grep ＋ベクトル検索で柔軟対応 |
| 監査ログ必須 | ローカル環境＝ガバナンス不要ではない |
| GPU管理 | Semaphoreで同時実行数を制限 |
| セッション永続化 | JSON で会話履歴をディスク保存 |

## 結論

「セキュリティ要件で外部通信禁止」という制約下でも、Ollamaのツール呼び出し機能とローカル埋め込みモデルを
組み合わせれば実用的なAgentic RAGが実装可能。ただし、ツール実行の検証・GPUリソース管理・監査ログ整備など、
運用面での配慮が不可欠である。
